# AGENTS.md

Context for AI coding agents (Claude Code, Cursor, Copilot, etc.) working in this
repository. Human contributors should start with the [README](./README.md); this file
is the machine-facing companion that keeps agents productive and safe.

> **Repo name vs. product name** — the repository is `meli-project-management`, but the
> product it ships is **`/retrospectool`**: a real-time, collaborative agile
> **retrospective** tool. It is a personal open-source project, *not* a Mercado Libre
> internal service, despite the repo name.

---

## What this app does

`/retrospectool` lets a team run a sprint retrospective on a shared board with three
columns:

| Column    | `pipeline` value | Meaning              |
| --------- | ---------------- | -------------------- |
| Good      | `good`           | What went well       |
| Bad       | `bad`            | What to improve      |
| Actions   | `action`         | Action items         |

**No login required.** Identity is anonymous and local (see
[Identity model](#identity-model-anonymous)); Clerk auth is deprecated behind a flag.
Everyone on the board sees changes **live** (Convex reactive queries). Core features:

- Create a retro board and share the URL; participants join automatically after
  choosing a display name (prompted by a modal on first create / first visit).
- Add notes to any column, optionally **anonymous**.
- **Like** notes, **assign** action items to participants, **reorder** via drag & drop.
- **Merge** notes: drag one card onto another, or multi-select and merge.
- Per-board **timer** and a **hide/blur** mode so notes stay hidden until reveal.
- **AI-generated action items** from the "Bad" notes (Vercel AI SDK → OpenAI / Anthropic).
- **Text-to-speech** playback of a note (ElevenLabs).
- "What's new" changelog widget (Olvy).

## Tech stack

- **Framework**: Next.js 13 (App Router, RSC) + React 18 + TypeScript (strict).
- **Backend / DB**: [Convex](https://convex.dev) — reactive database + serverless
  queries/mutations. Real-time sync is provided by Convex, there is no custom websocket layer.
- **Identity**: anonymous, **local** (localStorage) — see
  [Identity model](#identity-model-anonymous). [Clerk](https://clerk.com) (Google sign-in)
  is **deprecated behind the `CLERK_AUTH_ENABLED` flag** in `src/config/features.ts`; its
  integration code is preserved but inactive.
- **AI**: [Vercel AI SDK](https://sdk.vercel.ai) (`ai`) with `@ai-sdk/openai` and
  `@ai-sdk/anthropic`.
- **Voice**: ElevenLabs (text-to-speech) via a thin service wrapper.
- **UI**: Tailwind CSS + SCSS, [shadcn/ui](https://ui.shadcn.com) (New York style) on Radix
  UI, PrimeReact, FontAwesome, Lucide icons, Lottie animations, react-toastify.
- **Drag & drop**: `@dnd-kit/core` + `@dnd-kit/sortable`.
- **Analytics**: Vercel Analytics + Speed Insights.
- **Node**: `24.x` (see [.nvmrc](./.nvmrc) and `engines` in package.json).

## Commands

```bash
npm ci             # install exactly per package-lock.json

npm run convex:dev # Convex dev server (run in a SECOND terminal; watches convex/)
npm run build      # production build
npm run start      # serve the production build
npm run lint       # next lint (ESLint)
```

**Local development needs both `npm run dev` and `npm run convex:dev` running at the same
time.** `convex dev` regenerates `convex/_generated/` and writes deployment values into
`.env.local`. See the [README](./README.md) for the full first-time setup (Clerk app +
JWT template, Convex project, environment variables).

There is currently **no automated test suite** and no CI. Validate changes with
`npm run lint` and a manual smoke test in the browser.

## Data model (Convex)

Defined in [`convex/schema.ts`](./convex/schema.ts):

- **users** `{ name, avatar?, tokenIdentifier }` — indexed `by_token`. `tokenIdentifier`
  is now the **local anon id** (was the Clerk JWT subject); `avatar` is a generated SVG
  data URI. Users are upserted when a display name is set. `tokenIdentifier` is **redacted**
  (blanked) before user docs are returned to clients — see Security notes.
- **retros** `{ name, ownerId, timer?, startTimer?, timerStatus?, notesShowingStatus?, status? }`
  — indexed `by_owner_id`.
- **notes** `{ body, pipeline, userId, retroId, anonymous?, mergeParentId?, likes?, position?, assignedTo? }`
  — indexed `by_retro_id`. `mergeParentId` links a merged child note to its parent;
  `likes` is an array of user ids; `position` drives sort order.
- **users_retro** `{ userId, retroId }` — join table for board membership; indexed
  `by_retro_id` and `by_user_id`.

---

## How the moving parts connect

- **Identity → data**: `IdentityProvider` (under `ConvexClientProvider`) owns the local
  identity and upserts it into Convex via `users.store`, keyed by the local `anonId`
  (stored in `tokenIdentifier`). The current user (`me`) is resolved by the Convex `_id`
  the client holds — never by the token, which is redacted out of query responses.
- **Real-time board**: `retro/[id]/page.tsx` subscribes with `useQuery`/custom hooks; any
  `useMutation` write re-renders every connected client automatically. Notes are grouped
  client-side into `good` / `bad` / `action` (plus merged `children`) in a `useMemo`.
- **AI action items**: client hook `useGenerateActionItems` → `POST /api/generate-actions`.
  The route (auth-gated only when Clerk is on) validates `items` and the `model` against the
  `MODELS` allowlist, then calls `CreateCompletion` (Vercel AI SDK). System prompts live in
  `src/services/system-content`. The result string is split on `;` into individual notes.
- **Text-to-speech**: a note's speaker button → `POST /api/speech` → `ElevenLabs` wrapper
  → audio blob streamed back.

## Identity model (anonymous)

The app has **no login**. Identity lives entirely in the browser:

- On first load, [`src/helpers/localIdentity.ts`](./src/helpers/localIdentity.ts) creates a
  stable `anonId` with `crypto.randomUUID()` and stores `{ anonId, name }` in localStorage
  (key `retrospectool.identity.v1`).
- When a display name is set (via the welcome/rename modal), the identity is upserted into
  Convex `users` (`tokenIdentifier = anonId`) and the returned `_id` becomes the user's id
  for notes/retros. **Renaming keeps the same `anonId`/`_id`** — only the display name (and
  the avatar's initial) change.
- The avatar is a **generated, deterministic SVG data URI** (color from a hash of the id,
  a sanitized `[A-Z0-9]` initial) — no external service, no user text in markup.
- The name modal is shown on first create and when opening a retro without a name yet
  (`IdentityProvider.ensureIdentity()` / `promptName()`).
- **Old Clerk users** cannot see their pre-migration retros: identity is a brand-new local
  id, unrelated to the previous Clerk-derived user rows.

## Conventions

- **TypeScript, strict mode.** Prefer explicit types on public function signatures.
- **Functional React components**, hooks-first. Client components are marked `'use client'`.
- **Data access lives in Convex**, not in the Next.js app. Add a query/mutation in
  `convex/*.ts` and call it via `useQuery`/`useMutation`; don't reach around Convex.
- **New shared UI primitives** go in `src/components/ui` (shadcn conventions in
  [components.json](./components.json)); feature components go in `src/components/<name>`.
- **Reusable client logic** goes in `src/helpers/hooks`; **pure helpers** in `src/helpers`.
- **Styling**: Tailwind utility classes first; component-scoped SCSS (`styles.scss`) only
  when needed. Use the `cn()` helper from `src/lib/utils.ts` to merge classes.
- **Formatting/lint**: Prettier ([.prettierrc.js](./.prettierrc.js)) + ESLint
  (`next lint`). Respect [.editorconfig](./.editorconfig). Run `npm run lint` before
  committing.
- **Never edit `convex/_generated/`** — it is regenerated by `convex dev`.

## Environment variables

Copy [`.env.example`](./.env.example) to `.env.local` and fill it in. **Never commit real
secrets** — `.env*.local` is gitignored.

| Variable                            | Where            | Secret? | Purpose                                             |
| ----------------------------------- | ---------------- | ------- | --------------------------------------------------- |
| `CONVEX_DEPLOYMENT`                 | `.env.local`     | no      | Written by `convex dev`; selects the deployment.    |
| `NEXT_PUBLIC_CONVEX_URL`            | `.env.local`     | no      | Convex endpoint; exposed to the browser by design.  |
| `OPENAI_API_KEY`                    | `.env.local`     | **yes** | Read implicitly by `@ai-sdk/openai`.                |
| `ANTHROPIC_API_KEY`                 | `.env.local`     | **yes** | Read implicitly by `@ai-sdk/anthropic`.             |
| `ELEVEN_LABS_API_KEY`               | `.env.local`     | **yes** | ElevenLabs TTS (only needed for the speech feature).|
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | `.env.local`     | no      | **Legacy/Clerk** — only if `CLERK_AUTH_ENABLED`.    |
| `CLERK_SECRET_KEY`                  | `.env.local`     | **yes** | **Legacy/Clerk** — only if `CLERK_AUTH_ENABLED`.    |
| `CLERK_JWT_ISSUER_DOMAIN`           | Convex dashboard | no      | **Legacy/Clerk** — used by `auth.config.js`.        |

With `CLERK_AUTH_ENABLED = false` (the default), **only the Convex vars are required** to
run; the AI/ElevenLabs keys are optional (feature-gated) and the Clerk vars are unused.
`NEXT_PUBLIC_*` values are inlined into the client bundle — only put non-secret values
there. Everything else is server-only; keep it out of client components and logs.

## Security notes

Follow these when extending the app (principles apply even though this is not a Mercado
Libre internal service):

- **Anonymous by design — no server-side authorization.** With Clerk off there is no
  authenticated principal; Convex mutations trust the client-supplied identity. The
  mitigation is that the `anonId` is an **unguessable, local bearer capability**
  (`crypto.randomUUID`) that is **never broadcast**: `toPublicUser` redacts `tokenIdentifier`
  from every query response (CWE-639). **Never render, log, or return the `anonId`/token to
  other clients**, and match the current user by Convex `_id`, not by the token.
- **Cost-incurring endpoints are unauthenticated in anonymous mode.** `/api/generate-actions`
  (auth-gated only when Clerk is on) and `/api/speech` forward user input to paid providers
  with no auth. `generate-actions` bounds abuse with input validation (item count/length +
  `MODELS` allowlist); **`/api/speech` still lacks auth and validation** — known tech debt,
  add rate limiting / validation before heavy production use. Don't copy the unauthenticated
  pattern without at least bounding input.
- **Validate external input** (body) against a strict shape/allowlist at the route handler
  (see `generate-actions`). Display names are normalized + length-capped in
  `localIdentity.normalizeName` and clamped again server-side in `users.store`.
- **XSS**: user text renders through React (auto-escaped); the SVG avatar embeds only a
  sanitized `[A-Z0-9]` initial and an id-derived color — never interpolate raw user input
  into the SVG or any markup.
- **Keep the AI prompt-injection guardrails.** The system prompts in
  `src/services/system-content` intentionally instruct the model to ignore embedded
  instructions in user notes — preserve this when editing prompts.
- **Randomness**: never `Math.random()` for ids/tokens — use `crypto.randomUUID()` /
  `crypto.getRandomValues()` (see `localIdentity.ts`).
- **Secrets**: never hardcode or log keys; keep them in `.env.local` / the Convex
  dashboard. Only `NEXT_PUBLIC_*` may be exposed to the client.
- The `.pre-commit-config.yaml` websec hook is intentional — do not remove it.

## Gotchas

- **Clerk is deprecated, not deleted.** `CLERK_AUTH_ENABLED` in `src/config/features.ts`
  gates every Clerk touchpoint (provider, middleware, navbar, sign-in/up pages, `InitUser`,
  the `generate-actions` auth check). Flip it to `true` (and restore the Clerk env vars) to
  revive login. Don't re-introduce direct `useUser()`/Clerk calls in the active path — go
  through `useIdentity()`.
- **Avatars are generated SVG data URIs**, so they render with plain `<img>` (with an
  inline `eslint-disable @next/next/no-img-element`), not `next/image` (which rejects data
  URIs). Keep that pattern for user avatars.
- **Bulk AI generation is disabled** in `retro/[id]/page.tsx`
  (`const showGenerateActionItemsButton = false`). The per-card AI action generation path
  is the active one. Flip that flag (and restore the commented condition above it) to
  re-enable board-wide generation.
- **Node `24.x`** is pinned via `.nvmrc` + `engines` (Vercel rejected 18.x).
- Client-only libs that touch `window`/`document` (Lottie, the Olvy widget) must be loaded
  with `next/dynamic({ ssr: false })` — the options must be an inline object literal.
- `next.config.js` sets `swcMinify: false` — leave it unless you know why it was disabled.
- A couple of Convex mutation names are misspelled but load-bearing: `assigne` and
  `unnasign` in `convex/notes.ts`. Don't "fix" the names without updating every call site.
- Remote images are restricted to `img.clerk.com` in `next.config.js`; add hostnames there
  before using `next/image` with other sources.

## Where to add a new feature

1. **Data change?** Update `convex/schema.ts` and add/adjust query/mutation functions in
   the relevant `convex/*.ts` file. `convex dev` regenerates the typed API.
2. **UI?** Add a component under `src/components/`, wire it into
   `src/app/retro/[id]/page.tsx` (or the relevant route), and pull data via a hook in
   `src/helpers/hooks/`.
3. **Something tied to the user?** Use `useIdentity()` for the current id/name/avatar and the
   name modal; don't call Clerk directly.
4. **New server capability?** Add an App Router handler under `src/app/api/<name>/route.ts`
   — validate inputs against a strict shape/allowlist (and gate on auth if/when Clerk is
   re-enabled). See Security notes.
5. Run `npm run lint`, smoke-test both dev servers, and update this file + the README if the
   architecture changed.
